# APUNTE 03: GITHUB Y EL FLUJO COMPLETO

## 1. Concepto Central

Git = El software que toma las fotos de tu código.
GitHub = La red social y el disco duro en la nube para esas fotos.

El problema que resuelve GitHub no es solo "guardar un backup de seguridad", es "cómo trabajo con otra persona en la misma cámara sin pisarnos los pies" y "cómo le muestro mi historial de fotos a un reclutador".

## 2. Los 3 Comandos Clave del Flujo Remoto

| Comando           | Significado Práctico                          | Qué hace en la analogía de la cámara                                          |
| ----------------- | --------------------------------------------- | ----------------------------------------------------------------------------- |
| `git clone [url]` | Descargar un repo completo de internet.       | Bajar una cámara ajena, con todas sus fotos y carretes a tu PC.               |
| `git remote -v`   | Ver a dónde apunta tu repositorio local.      | Revisar cuál es el álbum de Google Photos al que está sincronizada tu cámara. |
| `git push`        | Sincronizar mis commits (fotos) hacia GitHub. | Darle al botón de "Subir" en el álbum de fotos (Sincronizar).                 |

## 3. El Flujo de Trabajo Completo (El Pan de Cada Día)

Este es el ciclo que repetirán en el 90% de su carrera profesional, sea en proyectos personales o en empresas, una y otra y otra vez:

1. **Escribir código** (Cambian archivos en su PC)
2. `git status` (Miran qué archivos cambiaron)
3. `git add .` (Le dicen "este sí, este también, este no" a la cámara)
4. `git commit -m "feat: [mensaje]"` (Toman la foto y le ponen un sticker que la describe)
5. `git push` (Sincronizan hacia la nube de GitHub)

## 4. Puntos Críticos y Soluciones (Salva-vidas del Instructor)

1. **Error: `fatal: not a git repository`**
   - _Por qué pasa:_ El alumno hizo clone, la carpeta bajó bien, pero intentó hacer `git status` o añadir archivos sin haber entrado a la carpeta.
   - _La Solución:_ Haz que escriban `pwd`. Verás que están fuera. La cura es `cd [nombre-de-la-carpeta]`.
2. **Error: `Updates were rejected because the remote contains work that you do not have locally.` (Error al hacer Push)**
   - _Por qué pasa:_ Alguien editó el archivo _directamente en GitHub_ (ej. el README) y luego intentó hacer `git push` desde su local con cambios distintos. Los historiales chocan.
   - _La Solución Rápida:_ Enseñar el verbo de bajada. `git pull` (Traer lo de internet hacia mi PC) -> Automerge o Merge -> `git push` (Ahora sí, subir la fusión).
3. **El dolor de cabeza: La Autenticación.**
   - Si les pide usuario y contraseña en terminal y les devuelve error 403: GitHub ya no acepta claves.
   - _El Parche Inmediato:_ Token clásico. Settings de GitHub -> Developer Settings -> PAT (Tokens) -> Classic -> Marcar la casilla "repo" y generar. Ese chorizo de letras y números es su contraseña temporal para que pasen el push.

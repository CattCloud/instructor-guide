# APUNTE 02: GIT LOCAL (LA CÁMARA INVISIBLE)

## 1. Concepto Central

Git es una herramienta que guarda "fotos" del estado de tus archivos para que siempre puedas regresar al pasado. NO es un sistema de respaldo en la nube (eso es GitHub). Git vive enteramente en el disco duro de la PC.

## 2. Los 3 Pilares de Git

1. **Velocidad Extrema:** Porque no consulta a internet, revisa archivos locales.
2. **Historial Inmutable:** Una vez que haces un commit, la firma criptográfica (SHA-1) asegura que nadie puede alterarlo sin que Git se dé cuenta.
3. **Trabajo en paralelo:** Almacenado como ramas.

## 3. El Flujo Analógico (La Sesión de Fotos)

La clave para enseñar Git sin frustrar al estudiante es que entienda DÓNDE está el archivo en cada paso:

| Paso / Comando                    | Nombre Técnico                   | Analogía                                                                | Lo que el estudiante ve / siente                                        |
| --------------------------------- | -------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `git init`                        | Repositorio Inicializado         | El fotógrafo entra a la sala.                                           | Aparece el (main) o (master) azul en la terminal. Todo empieza en cero. |
| (Crear archivos)                  | Untracked Files                  | Estás en el backstage. La cámara aún no sabe que estás.                 | Archivos en rojo brillante. Git dice _"Untracked files present"_.       |
| `git add [archivo]` o `git add .` | Staging Area (El Índice)         | Sales al escenario y poses congelado frente a la cámara. Dices "listo". | Archivos en verde. Git dice _"Changes to be committed"_.                |
| `git commit -m "mensaje"`         | The Repository (El Commit Local) | ¡CLICK! El fotógrafo toma la foto y la imprime.                         | Aparece el hash del commit `[main 4f2c... ]` y _"X files changed"_.     |

## 4. El Comando Intermedio INDISPENSABLE

**`git status`**: Es el radar. Debe ejecutarse **SIEMPRE** entre cualquier otro comando de Git, especialmente antes de un commit para evitar meter archivos basura a la foto (node_modules, imágenes inmensas sin comprimir).

- Rojo: Modificado o nuevo, pero el fotógrafo aún no lo sabe.
- Verde: Posando, listo para la foto de `commit`.
- Limpio: "Nothing to commit, working tree clean". No hay cambios pendientes desde la última foto.

## 5. Anatomía de un Mensaje de Commit Profesional

Un error común es pensar que "arreglado", "cambios varios" o "test" son buenos mensajes.
La regla de oro es el **VERBO EN IMPERATIVO** o la convención estandarizada:

- `feat: [qué]`: Añade algo nuevo. `feat: agregar botón de contacto`
- `fix: [qué]`: Arregla algo roto. `fix: corregir enlace del menú`
- `docs: [qué]`: Cambia texto. `docs: actualizar el Readme`
